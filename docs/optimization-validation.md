## 手算口径

- 第 0 槽记录期初待处理量，`POH0`、`PAB0`、`NR0` 仍为 `-1` 占位；它的需求与到货在第 1 期合并一次。
- 例：期初库存 5、分配 1、安全库存 4，`GR0=6`、`GR1=29`，`SR0=2`、`SR1=3`。第 1 期接收前库存为 `5+2+3-1-6-29=-26`，净需求 30。FOQ 批量 10 时接收 30，期末库存 4。第 2 期再需求 8，则补一批 10，期末库存 6。
- 提前期 2、安全时间 1 时，上例第 1 期接收的 30 应在第 `-2` 期下达；该期段和数量单独保存，不写入 `POR0` 冒充期内下达。
- 三层例：A 下达 10，A→B 用量 2，A→C 用量 3，B→D 用量 4，C→D 用量 5。B 需求 20、C 需求 30，D 合计 `20×4+30×5=230`。输入顺序改变不影响结果。
- 若 B 的提前期为 3，B 在 `-2` 期应下达 20，且 B→C 用量为 3，则 C 的原始逾期需求为 `{-2:60}`，同时纳入 `GR0=60`；这表示逾期待处理量，不表示已按时满足。

## 结构与事务边界

`BomGraph` 统一检查物料标识、边、循环和 LLC。LLC 必须等于从根节点到物料的最长路径层数，计算顺序来自拓扑排序；顶层输入不再与中间物料的计算结果重复叠加。缺失输入、重复记录、非法数量不再补成零或跳过。

`MrpRecalculationService` 负责读输入、计算、删除旧结果和保存新结果。事务隔离为 `REPEATABLE_READ`，先锁定 `t_mrp_recalculation_lock` 的唯一行，再建立输入快照。第二次重算必须等前一次提交或回滚后才能读取自己的输入快照。普通输入编辑仍可提交，由下一次计算读取；系统不声称一次已开始的计算能包含之后的编辑。

所有删除/保存与期外集合映射位于同一事务中；`Transactions` 统一回滚并重抛原始异常，回滚失败附在原异常上。`DBO` 已移除失败后返回 `null`、`false` 或空结果的行为。应用卸载时关闭 SessionFactory，并注销本应用 JDBC 驱动及其清理线程。

数据库升级使用 V1 后接 [V3](../db/migration/V3__atomic_batches_and_past_due.sql)，实际集成测试也执行这两份 SQL。V2 预备设计未启用。

## 复现

```powershell
# 需要 JDK 8、Maven 3.9 在 PATH
powershell -NoProfile -File scripts\verify.ps1

# Python 3；副本由脚本创建并核验归属后删除
python scripts\check_verify_failures.py

# 仅填写专用测试 MySQL 服务，URL 不含已有数据库名
$env:MRP_TEST_MYSQL_URL = 'jdbc:mysql://127.0.0.1:33317/'
$env:MRP_TEST_MYSQL_USER = 'test_admin'
$env:MRP_TEST_MYSQL_PASSWORD = '测试服务器密码'
powershell -NoProfile -File scripts\verify.ps1 -Integration
```

集成测试为实际 WAR 单独启动一个仅含容器依赖的 JVM，部署到 `/mrp`，实际请求 `MRP_domrp.action`，检查 HTTP 200 和页面中的 B、C 物料结果。它不会借用 Maven 测试进程中的 Struts/Hibernate 依赖；容器正常停止，所有随机测试库均清理。

Java 8 的 Windows 原生启动器在本机不能正确处理中文绝对类路径，因此脚本与独立 JVM 使用相对 `target` 路径，JDK 安装路径使用 ASCII 目录。没有以缩减 WAR 检查、伪造响应或跳过部署来处理该问题。
